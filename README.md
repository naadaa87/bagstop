# 백스톱 (BagStop) 짐보관 플랫폼

> Leave it with us. — 짐은 백스톱에 맡기고, 여행은 가볍게.

동네 카페·음식점·편의점·숙소가 여행자의 짐을 맡아 주고, 그 가게의 메뉴나 서비스를 함께 파는 플랫폼입니다. 한국을 찾는 해외 여행객이 주 고객입니다. 마스코트 캐릭터 이름은 '짐보(Jimbo)'입니다.

고객 웹, 백스톱 호스트센터, 백스톱 Admin이 한 저장소에 들어 있습니다. 세 화면은 같은 API와 같은 데이터베이스를 씁니다.

| 화면 | 주소 | 쓰는 사람 |
|---|---|---|
| 고객 웹 | `/ko` `/en` `/ja` `/zh-hans` `/zh-hant` | 짐을 맡기는 손님 (5개 언어) |
| 백스톱 호스트센터 | `/host/` | 짐을 맡아 주는 가게 사장님 |
| 백스톱 Admin | `/admin/` | 본사 운영팀 |

GitHub에 올리고 Cloudflare Pages에 연결하면 바로 배포됩니다. 빌드 과정이 없어서 터미널이나 별도 프로그램은 필요하지 않습니다.

---

## 1. 배포 순서 (브라우저만 사용)

### A. GitHub에 올리기
1. GitHub에서 새 저장소를 만듭니다. (예: `bagstop`, Private 권장)
2. 이 폴더의 파일을 **폴더 구조 그대로** 올립니다. 저장소 화면의 **Add file → Upload files**에 폴더째 끌어다 놓으면 됩니다.
   - `public`, `functions`, `lib` 세 폴더와 `README.md`가 저장소 맨 위에 보여야 합니다.

### B. Cloudflare Pages 프로젝트 만들기
1. Cloudflare 대시보드 → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
2. 위 저장소를 고르고 빌드 설정을 이렇게 둡니다.
   - Framework preset: **None**
   - Build command: **(비워 둠)**
   - Build output directory: **`public`**
3. **Save and Deploy**. 첫 배포 직후에는 데이터베이스가 없어서 "서비스 준비 중" 화면이 나옵니다. 정상입니다.

### C. D1 데이터베이스 만들기
1. 대시보드 → **Storage & Databases → D1 SQL Database** → **Create** → 이름 `bagstop`.
2. 표는 여기서 만들지 않습니다. F단계에서 Admin의 **DB 준비하기** 버튼이 대신 만들어 줍니다.

### D. 바인딩과 환경 변수 연결
Pages 프로젝트 → **Settings**에서 설정합니다.

**Bindings (필수)**

| 종류 | Variable name | 값 |
|---|---|---|
| D1 database | `DB` | 위에서 만든 `bagstop` |

**Environment variables (권장)**

| 이름 | 값 | 설명 |
|---|---|---|
| `SITE_URL` | `https://프로젝트명.pages.dev` 또는 연결한 도메인 | 메일 속 링크, 사이트맵, 검색엔진용 주소에 쓰입니다 |

### E. 다시 배포
바인딩은 다음 배포부터 적용됩니다. **Deployments → 가장 최근 배포 → Retry deployment**를 누릅니다.

### F. Admin에서 설치 마치기
1. `https://내주소/admin/` 에 들어갑니다.
2. **DB 준비하기**를 누릅니다. 표와 기본 정책, 지역 4곳(홍대·연남 / 명동·을지로 / 성수 / 서울역·용산), 기본 안내문이 들어갑니다.
3. **최초 관리자 만들기**에서 이름·이메일·비밀번호를 정합니다. 이 계정이 총괄 권한을 가집니다.
   - 이 화면은 관리자가 한 명도 없을 때만 열립니다. 배포한 뒤 바로 만들어 두세요.

### G. 체험용 데이터로 둘러보기 (선택)
Admin → **시스템 → 체험용 데이터 넣기**를 누르면 스팟 6곳과 예약·리뷰가 들어갑니다.
- 고객 웹에서 예약부터 결제(테스트)까지 해 볼 수 있습니다.
- 화면에 나오는 체험용 호스트 계정으로 호스트센터도 볼 수 있습니다.
- **실제 운영을 시작하기 전에 꼭 "모두 지우기"를 눌러 주세요.** 체험용 호스트 계정의 비밀번호는 누구나 알 수 있는 값입니다.

### H. 도메인 연결
Pages 프로젝트 → **Custom domains**에서 도메인을 연결하고, `SITE_URL`을 그 주소로 바꾼 뒤 다시 배포합니다.

## 2. 실제 운영 전에 정해야 하는 것

코드는 아래 항목이 비어 있어도 돌아가게 만들었습니다. 다만 그대로 손님을 받으면 안 되는 것들입니다.

| 항목 | 지금 상태 | 해야 할 일 |
|---|---|---|
| 결제 | **테스트 결제** (실제 청구 없음) | PG 계약 후 포트원 V2 값 3개를 환경 변수로 넣습니다 (아래 3번) |
| 수수료·운영 기준 | 임시 기본값 (보관분 15%, 추가분 8%, 건당 최소 500원 등) | Admin → 가격·수수료 정책에서 사업 조건에 맞게 바꿉니다 |
| 지역 기준가 | 모든 지역이 같은 임시값 (소형 5,200 / 일반 8,600 / 대형 11,900원, 범위 60~150%) | 지역별 시세를 확인해 조정합니다 |
| 이용약관·개인정보 처리방침 | 구조 설명용 초안 | 법률 검토를 거친 내용으로 Admin → 콘텐츠에서 바꿉니다 |
| 보장 한도 | 건당 30만 원 (임시) | 보험·보상 재원을 정한 뒤 맞춥니다 |
| 외국어 문구 | 영어·일본어·중국어(간체·번체) 작성 완료 | 출시 전 원어민 검수를 권합니다 |
| 메일 발송 | 발송 기록만 남김 | Resend 키를 넣으면 실제로 나갑니다 (아래 3번) |
| 정산 이체 | Admin에서 내역만 만들고 "지급 완료" 표시 | 실제 이체는 은행(또는 PG 지급대행)에서 따로 해야 합니다 |

## 3. 선택 설정

모두 Pages 프로젝트 → Settings에서 넣고 다시 배포하면 적용됩니다. 지금 연결 상태는 Admin → 시스템에서 볼 수 있습니다.

| 이름 | 종류 | 넣으면 달라지는 것 |
|---|---|---|
| `PORTONE_STORE_ID` `PORTONE_CHANNEL_KEY` `PORTONE_API_SECRET` | 환경 변수 (Secret 권장) | 세 값이 모두 있으면 테스트 결제 대신 포트원 V2 카드 결제로 바뀝니다. 환불도 포트원으로 나갑니다. 실제 결제를 열기 전에 포트원 테스트 채널로 결제·취소를 꼭 한 번씩 해 보세요 |
| `RESEND_API_KEY` `MAIL_FROM` | 환경 변수 | 예약 확정·취소·보관 안내 메일이 실제로 발송됩니다. `MAIL_FROM` 예: `BagStop <no-reply@내도메인>` |
| `FILES` | R2 bucket 바인딩 | 사진을 R2에 저장합니다. 없으면 D1에 저장합니다 (사진이 많아지면 R2로 바꾸세요) |
| `AI` | Workers AI 바인딩 | 손님과 호스트가 주고받는 메시지를 자동 번역합니다. 없으면 원문 그대로 전달됩니다 |

지도는 OpenStreetMap 타일을 씁니다. 방문자가 늘면 유료 타일 서비스로 바꾸는 편이 안전합니다 (`public/assets/js/lib/core.js`의 `TILE` 한 줄).

## 4. 들어 있는 기능

**고객 웹**
- 지역·지도에서 스팟 찾기 (가격 말풍선, 크기·세트·영업 중 필터), 지역별 안내 페이지
- 스팟 상세: 가격표, 세트(짐앤○○ / Bag & ○○), 백스톱 혜택, 받는 시간, 위치와 지도 앱 3종 바로가기, 리뷰
- 예약: 짐만 맡기기 또는 세트 → 짐 개수 → 맡기는·찾는 시각 → 실시간 견적 → 결제
- 예약 확인: QR 코드·확인 번호·번호표, 맡긴 짐 사진, 호스트와 메시지, 한국어 문장 카드, 찾는 시각 변경(연장), 취소, 초과 요금 결제, 리뷰, 사고 접수
- 회원가입 없이 예약번호 + 이메일로 예약 찾기 (여권번호는 받지 않음)
- 호스트 모집 페이지와 수익 계산기, 도움말·규정·문의

**백스톱 호스트센터**
- 가입 → 호스트 신청(유형·서류) → 심사 → 스팟 공개까지 안내하는 시작하기 화면
- 오늘: 맡으러 올 예약, 보관 중인 짐, 승인 대기, 시간대별 자리 사용량
- QR 체크인: 카메라로 QR 찍기 또는 예약번호 입력 → 짐 사진 2장 이상 + 번호표 → 맡기기 완료 / 찾기 완료
- 받는 시간·물량: 요일·시간대별 칸 수, 맡기기·찾기 구분, 밤새 보관 물량, 쉬는 날
- 가격: 크기별 잠깐·하루·1주·1달 가격을 지역 기준 범위 안에서 직접 설정
- 세트·추가 서비스: 따로 살 때보다 싸야 등록되고, 보관분·추가분·수수료·정산액을 바로 보여 줌
- 가게 문 스티커: 'BAG STOP' 스티커를 A5로 인쇄하거나 SVG로 내려받음. QR을 찍으면 그 스팟 예약 화면이 열려서, 가게 앞에서 바로 예약할 수 있음
- 예약 관리(승인·거절·취소), 메시지, 리뷰 답글, 정산 내역, 사고 소명, 계좌 등록

**백스톱 Admin**
- 대시보드(처리할 일, 이번 달 거래), 호스트 심사, 스팟 운영 중지
- 예약 조회, 운영자 취소·환불, 대리 찾기 처리
- 가격·수수료 정책: 수수료 a·b·c, 지역별 기준가와 범위, 운영 기준(노쇼·초과 요금·보장 한도 등)
- 정산 만들기·보류·지급 완료, 사고 판정과 보상(호스트 부담액은 다음 정산에서 차감)
- 리뷰 숨김, 문의 답변, 콘텐츠(FAQ·규정·약관) 편집, 알림 내역
- 관리자 계정과 역할(총괄·운영·CS·정산·콘텐츠·조회), 처리 기록

**정책 계산 (lib/policy.js)**
- 요금: 잠깐(4시간 이내) / 하루 / 오래(일 단위, 1주·1달 가격 적용)
- 세트 안분: 보관분 = 세트가 × 보관가 ÷ 따로 살 때 가격, 추가분 = 세트가 − 보관분
- 수수료: max(보관분 × a + 추가분 × b, c), 호스트 정산액 = 판매가 − 수수료
- 물량: 보관하는 내내 (이미 잡힌 칸 + 새 예약) ≤ 그 시간대 칸 수. 동시에 들어온 예약은 먼저 들어온 쪽만 남김
- 취소: 맡기는 시각 전 전액 환불, 준비형 세트는 마감 뒤 보관분만 환불, 호스트 취소는 전액 환불

**다음 단계로 남긴 것**
백스톱 쿠폰, 백스톱 프렌즈(추천), 오늘 할인, 주변 시세 보기, 호스트 통계, 직원 계정, 스팟 여러 곳 운영, 알림톡·웹 푸시, 베트남어. 가정형·공간형 호스트는 신청과 심사까지 열려 있고, 승인은 운영팀이 시범 범위를 정해 진행하도록 했습니다.

## 5. 폴더 구조

```
public/                 정적 파일 (Cloudflare Pages가 그대로 내보냅니다)
  index.html            고객 웹
  host/index.html       호스트센터
  admin/index.html      Admin
  assets/css            화면 스타일 (색은 base.css 맨 위에서 바꿉니다)
  assets/js/customer    고객 웹 화면, i18n/ 에 언어별 문구
  assets/js/host        호스트센터 화면
  assets/js/admin       Admin 화면
  assets/js/lib         공통 도구
  assets/img            마스코트 짐보, 공유 이미지(og.png)
  assets/vendor         외부 라이브러리 (Preact, Leaflet, QR)
functions/              서버 진입점 (얇게, 실제 코드는 lib/)
lib/                    서버 코드
  schema.js             데이터베이스 구조와 정책 기본값
  policy.js             요금·세트·수수료·물량·취소 계산
  core.js               예약의 한 살이 (견적 → 결제 → 맡기기 → 찾기)
  api-public.js         고객 웹 API
  api-host.js           호스트센터 API
  api-admin.js          Admin API
  services.js           결제·메일·번역·파일
  pages.js              언어별 주소, 검색엔진용 정보, 사이트맵
  seed.js               기본 안내문, 체험용 데이터
```

## 6. 고칠 때

- **문구**: 고객 웹은 `public/assets/js/customer/i18n/` 의 언어별 파일, 메일 문구는 `lib/services.js`.
- **색·글자**: `public/assets/css/base.css` 맨 위 `:root`.
- **정책 기본값**: 운영 중에는 Admin에서 바꾸면 됩니다. 처음 설치할 때의 값은 `lib/schema.js`.
- **데이터베이스 구조**: `lib/schema.js`의 `SCHEMA_VERSION`을 올리고 새 컬럼을 `ALTERS`에 추가하면, 배포 뒤 첫 요청에서 자동으로 반영됩니다. (Admin → 시스템 → "DB 준비하기 다시 실행"으로도 됩니다)
- 파일을 고쳐 GitHub에 올리면 Cloudflare가 자동으로 다시 배포합니다.

## 7. 자주 묻는 문제

- **"서비스 준비 중" 화면만 나와요** → D단계의 `DB` 바인딩을 넣었는지, 그 뒤에 다시 배포했는지, `/admin/`에서 DB 준비하기를 눌렀는지 확인해 주세요.
- **스팟이 고객 화면에 안 보여요** → 호스트가 승인 상태이고, 스팟이 "공개 중"이어야 합니다. 사진·지도 위치·받는 시간·가격이 모두 있어야 공개할 수 있습니다.
- **예약이 "자리가 모자라요"로 막혀요** → 호스트센터의 받는 시간·물량에서 그 시간대 칸 수를 확인해 주세요. 영업시간 밖까지 걸치는 예약은 밤새 보관 물량이 있어야 합니다.
- **호스트센터 카메라가 안 켜져요** → 브라우저의 카메라 권한을 허용해야 합니다. 안 되면 예약번호와 확인 번호 4자리를 직접 입력하면 됩니다.
